# 작업 관리

개별 작업은 `templates/FEATURE.md` 또는 `templates/BUG.md`를 복사해 `TASK-001.md`처럼 만든다.

## 상태 정의

- 대기: 명세 작성 중이거나 아직 시작하지 않음
- 준비: 목적, 범위와 완료 조건이 확정됨
- 진행: 구현 또는 검증 중
- 검토: 구현을 마치고 완료 조건을 확인 중
- 완료: `docs/DEFINITION_OF_DONE.md`의 모든 적용 항목 충족
- 보류: 외부 결정이나 입력이 필요하며 이유가 기록됨

## 작업 목록

| 번호 | 제목 | 상태 | 명세 | 비고 |
|---|---|---|---|---|
| TASK-003 | 프로젝트 기반과 실행 경계 초기화 | 대기 | `tasks/TASK-003.md` | 런타임과 workspace 도구 확정 후 준비 상태로 전환 |
| TASK-002 | 근거 데이터 모델과 승인 워크플로 설계 | 대기 | `tasks/TASK-002.md` | TASK-003 완료 후 준비 상태로 전환 |
| TASK-001 | 상황별 육아 가이드 탐색 화면 | 대기 | `tasks/TASK-001.md` | TASK-002의 publication snapshot 확정 후 준비 상태로 전환 |

## 작업 요청 예시

```text
프로젝트의 AGENTS.md와 관련 문서를 먼저 확인하고
tasks/TASK-001.md를 기준으로 작업해줘.

관련 코드 조사 → 변경 계획 → 구현 → 테스트 →
docs/DEFINITION_OF_DONE.md 기반 완료 판정 순서로 진행해.
확인하지 못한 내용은 추측하지 말고 미검증으로 보고해줘.
```
