# TASK-002 근거 데이터 모델과 승인 워크플로 설계

## 목적

검토된 대표 육아 가이드를 안전하게 저장하고 공개할 수 있도록 출처, 근거 주장, 평가, 가이드 버전과 승인 상태의 최소 데이터 모델 및 검증 규칙을 정의한다.

## 사용자

- 사용자 역할: 콘텐츠 편집자, 근거 검토자와 개발자
- 시작 조건: `docs/ARCHITECTURE.md`, `docs/EVIDENCE_GOVERNANCE.md`와 `docs/AI_RESPONSE_POLICY.md`를 확인한다.

## 범위

- 포함:
  - Source, Evidence Claim, Evidence Assessment, Guide, Guide Version, Review와 Publication 관계
  - 라이선스, 철회·정정, 적용 연령, 근거 등급과 재검토 기한
  - 초안에서 공개 및 보관까지의 상태 전이 규칙
  - 공개 가능한 가이드만 조회하는 데이터 접근 규칙
  - 대표 상황 3개를 수용할 수 있는 검증용 데이터 구조
  - 마이그레이션, 테스트와 복구 계획
- 제외:
  - 외부 자료 자동 수집기
  - 운영자용 편집 화면
  - 자유 질문과 AI 답변 생성
  - 실제 의료·응급 콘텐츠 공개
  - 커뮤니티 자료 수집

## 사용자 흐름

1. 편집자가 출처와 라이선스 정보를 등록한다.
2. 출처에 연결된 근거 주장과 평가를 등록한다.
3. 근거를 참조하는 가이드 초안 버전을 만든다.
4. 검토자가 승인, 수정 요청 또는 반려 상태를 기록한다.
5. 승인 요건을 충족한 가이드 버전만 공개된다.
6. 출처 철회 또는 검토 기한 경과 시 연결 가이드가 재검토 대상으로 식별된다.

## 완료 조건

- [ ] 각 핵심 엔터티와 관계, 필수 필드 및 불변 조건이 스키마로 표현된다.
- [ ] 식별자 또는 내용 해시를 이용한 출처 중복 방지 규칙이 있다.
- [ ] 라이선스 미확인 자료의 원문 저장과 공개를 거부한다.
- [ ] 미승인, 검토 기한 경과 또는 철회 근거에 의존한 가이드는 공개 조회 결과에 포함되지 않는다.
- [ ] 상태 전이에서 허용되지 않은 순서와 중복 승인을 거부한다.
- [ ] 작성자·검토자·변경 시점과 변경 사유를 감사할 수 있다.
- [ ] 정상, 누락, 잘못된 상태 전이와 공개 권한에 대한 자동 테스트가 통과한다.
- [ ] 마이그레이션 적용 및 되돌리기 또는 복구 절차가 문서화된다.

## 예외 및 경계 상황

- DOI, PMID 또는 ISBN이 없거나 중복되는 자료
- 하나의 자료에 여러 버전, 정정 또는 철회가 있는 경우
- 근거 등급 또는 라이선스가 미평가인 경우
- 가이드가 서로 충돌하는 여러 근거를 참조하는 경우
- 승인 직후 핵심 출처가 철회되는 경우
- 검토 기한과 시간대 경계
- 동시에 같은 가이드 초안을 수정 또는 승인하는 경우

## 데이터·보안 영향

- 추가·변경·삭제되는 데이터: 근거 및 가이드 관련 핵심 테이블과 상태 이력이 추가된다.
- 개인정보 여부: 콘텐츠 작성자와 검토자의 업무 식별정보가 필요할 수 있다. 실제 인증 설계 전에는 개인 계정을 저장하지 않는다.
- 인증 및 권한 조건: 공개 읽기, 편집, 검토와 공개 권한을 서버에서 분리해야 한다.
- 로그 및 외부 전송 영향: 이 작업은 외부 전송을 포함하지 않는다.
- 복구: 초기 데이터라도 마이그레이션 전 백업과 복원 가능한 시드 또는 내보내기 방법을 마련한다.

## 검증 계획

- 단위 테스트: 필수 필드, 라이선스, 연령 범위, 상태 전이와 재검토 판정
- 통합 테스트: 엔터티 관계, 트랜잭션, 동시 승인과 공개 전용 조회
- 사용자 흐름 테스트: 출처 등록부터 승인된 가이드 공개까지의 최소 흐름
- 수동 확인: 스키마가 대표 상황 3개와 출처 추적 화면 요구를 수용하는지 검토

## 구현 전 확정 사항

- ORM과 마이그레이션 도구
- PostgreSQL 개발·테스트 환경
- 근거 등급 판정 절차의 전문가 검토 범위
- 첫 대표 상황 3개와 데모 콘텐츠 표시 방식

## 작업 기록

- 상태: 대기
- 결정 사항: 원문, 근거 평가와 사용자용 가이드를 분리하고 승인된 버전만 공개한다.
- 미검증 사항: 전문가 검토 절차, 실제 콘텐츠 라이선스와 운영자 인증 방식
- 남은 위험: 데이터 모델이 근거 평가 방법을 지나치게 단순화하거나 검토 책임을 기술적 상태값으로 대체할 가능성
