# 배포, 백업 및 복구 기준

## 환경

- 개발, 테스트와 운영 환경을 분리한다.
- 환경별 주소, 비밀정보, 외부 서비스 모드와 데이터베이스를 확인한다.
- 운영에서 디버그 모드와 상세 내부 오류 출력을 비활성화한다.
- 필수 환경변수는 값이 아닌 이름과 목적만 문서화한다.

## 배포 전

- [ ] 관련 자동 테스트와 빌드가 통과했다.
- [ ] 운영 환경에서 핵심 사용자 흐름의 검증 계획이 있다.
- [ ] 데이터베이스 마이그레이션과 호환성을 확인했다.
- [ ] 비가역 데이터 변경 전 백업을 확인했다.
- [ ] 변경 내용, 사용자 영향과 점검 방법을 정리했다.
- [ ] 이전 버전으로 되돌리는 절차를 확인했다.

## 배포 후

- [ ] 애플리케이션 상태와 오류율을 확인했다.
- [ ] 로그인, 저장 등 핵심 흐름을 확인했다.
- [ ] 데이터 정합성과 마이그레이션 결과를 확인했다.
- [ ] 응답 시간, 자원 사용량과 외부 서비스 오류를 확인했다.
- [ ] 문제가 생기면 중단·복구할 판정 기준이 있다.

## 백업

- 자동 백업 주기, 보관 기간, 저장 위치와 접근 권한을 정한다.
- 운영 시스템 장애와 분리된 위치에 복구 가능한 사본을 둔다.
- 백업 성공 여부를 관찰하고 정기적으로 실제 복원 테스트를 수행한다.
- 허용 가능한 데이터 손실량과 복구 시간을 제품 요구에 맞게 정한다.

## 장애 대응

1. 추가 피해와 데이터 변경을 제한한다.
2. 증상, 발생 시간, 영향 범위와 최근 변경을 기록한다.
3. 데이터 손상 여부와 복구 필요성을 판단한다.
4. 필요하면 검증된 이전 버전 또는 백업으로 복구한다.
5. 사용자에게 영향과 현재 상태를 전달한다.
6. 근본 원인을 분석하고 재발 방지 테스트와 관찰 항목을 추가한다.
