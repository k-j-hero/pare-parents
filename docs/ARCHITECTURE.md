# 시스템 아키텍처

## 목표

Pare의 초기 아키텍처는 콘텐츠 신뢰성, 모바일 사용성, 낮은 운영 복잡도와 향후 확장을 함께 만족해야 한다. 사용자 서비스와 근거 생산 시스템의 안전 경계는 분리하되, 검증 전에는 불필요한 분산 시스템을 도입하지 않는다.

## 기본 구조

초기 시스템은 하나의 저장소에서 운영하는 모듈형 모놀리스와 별도의 비동기 수집 작업으로 구성한다.

```text
공식 API·허가된 자료
        |
        v
근거 수집 작업 -> 원문 저장소
        |
        v
PostgreSQL: Source -> Evidence -> Guide -> Review -> Publication
        |                         |
        |                         +-> 운영자·전문가 검토 화면
        v
승인·공개된 가이드만 조회
        |
        v
Pare 사용자 웹
```

## 시스템 경계

### 사용자 웹

- 모바일 우선 상황 탐색과 공개 가이드 조회를 제공한다.
- 공개 승인된 가이드 버전만 읽을 수 있다.
- 초기 버전은 로그인, 자유 입력과 개인화 저장을 제공하지 않는다.
- 서버 렌더링을 우선하고 상호작용이 필요한 최소 영역만 클라이언트에서 실행한다.

### 편집 및 검토 영역

- 원문, 근거 주장, 근거 평가와 사용자용 가이드를 구분한다.
- 초안 작성, 수정 요청, 승인, 공개와 보관 상태를 관리한다.
- 작성자, 검토자, 변경 사유와 시점을 감사 가능하게 기록한다.
- 공개 권한과 전문 검토 권한을 분리할 수 있게 설계한다.

### 근거 수집 작업

- 공식 API 또는 명시적으로 허용된 경로만 사용한다.
- 수집, 중복 제거, 라이선스 확인, 철회·정정 확인과 구조화를 수행한다.
- 자동화 결과는 공개하지 않고 검토 대기 상태로 저장한다.
- 사용자 요청을 처리하는 웹 프로세스와 실패 및 재시도 범위를 분리한다.

## 기술 기준

현재 승인된 방향은 다음과 같다. 구체적인 제품과 버전은 프로젝트 초기화 작업에서 잠금 파일과 함께 확정한다.

- 언어: TypeScript
- 웹: Next.js 기반 반응형 웹
- 기본 데이터베이스: PostgreSQL
- 원문 파일: 라이선스가 허용하는 자료만 S3 호환 오브젝트 스토리지에 저장
- 검색: 초기에는 구조화 필터와 PostgreSQL 전문 검색
- 의미 검색: 데이터와 평가셋이 충분할 때 `pgvector` 등 PostgreSQL 확장으로 검토
- 비동기 작업: 웹과 코드를 공유하되 독립 실행 가능한 worker
- 배포: 개발·테스트·운영 환경이 분리된 관리형 서비스 우선

## 모듈 경계

```text
apps/web                 사용자 및 운영자 웹
packages/domain          출처·근거·가이드·검토 규칙
packages/database        스키마, 쿼리와 마이그레이션
packages/evidence        근거 분류와 출처 처리
packages/ui              공통 UI와 접근성 기준
workers/ingestion        외부 자료 수집과 갱신
```

실제 디렉터리는 초기화 작업에서 확정한다. 모듈은 직접 데이터 구조를 우회하지 않고 공개된 도메인 인터페이스를 통해 상호작용한다.

## 핵심 데이터 흐름

1. 수집 작업이 자료 메타데이터와 허용된 원문을 가져온다.
2. 식별자와 내용 해시로 중복을 확인하고 라이선스 및 철회 상태를 기록한다.
3. 편집자가 자료에서 검증 가능한 근거 주장을 분리한다.
4. 검토자가 근거 확실성, 적용 범위와 위험을 평가한다.
5. 작성자가 근거 주장을 사용자용 가이드와 연결한다.
6. 승인된 특정 가이드 버전만 공개 상태로 전환한다.
7. 사용자 서비스는 공개 뷰 또는 공개 전용 쿼리만 사용한다.
8. 출처가 철회·정정되거나 검토 기한이 지나면 연결된 가이드를 재검토 대상으로 표시한다.

## 데이터와 권한 원칙

- 공개 데이터, 검토 중 데이터와 원문 파일의 접근 권한을 분리한다.
- 사용자 웹의 데이터베이스 역할은 공개된 레코드에 대한 읽기 권한만 갖는다.
- 운영자 변경은 서버 측 인증·권한 검사와 감사 로그를 거친다.
- 사용자 또는 아동 데이터가 도입되면 별도 위협 모델과 서버 측 행 단위 권한 정책을 마련한다.
- 스키마 변경에는 순방향 마이그레이션, 이전 버전 호환성, 백업과 복구 절차가 필요하다.

## 확장 기준

다음 조건이 측정되기 전에는 별도 검색 서비스, 벡터 데이터베이스, 메시지 브로커 또는 마이크로서비스를 도입하지 않는다.

- PostgreSQL로 충족할 수 없는 검색 품질 또는 지연 목표가 확인됨
- worker 처리량과 재시도 요구가 현재 작업 방식의 한계를 초과함
- 독립 배포가 필요한 팀 또는 장애 격리 요구가 생김
- 실제 부하 테스트로 병목이 재현됨

커뮤니티, 강좌와 커머스는 각각 별도 도메인 모듈로 추가하며 근거 저장소에 직접 쓰지 못하게 한다.

## 미정 사항

- 호스팅 제공자와 배포 지역
- ORM과 마이그레이션 도구
- 인증 제공자와 운영자 권한 체계
- 백업 주기, RPO와 RTO
- 관찰 도구와 운영 비용 한도

미정 사항은 관련 작업 명세와 `docs/DECISIONS.md`에서 확정한다.
