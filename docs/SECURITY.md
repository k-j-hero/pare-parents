# 보안 및 개인정보 기준

## 비밀정보

- API 키, 비밀번호, 토큰, 인증서 개인키와 운영 접속정보를 저장소나 채팅에 기록하지 않는다.
- 비밀정보는 환경변수 또는 전용 비밀 저장소에서 주입한다.
- 예제 설정에는 가짜 값만 사용하고 비밀정보 파일은 버전 관리에서 제외한다.
- 노출된 비밀정보는 파일에서 지우는 데 그치지 않고 폐기하고 재발급한다.
- 개발, 테스트와 운영 자격증명을 분리한다.

## 인증과 세션

- 비밀번호는 검증된 알고리즘으로 해시하며 원문으로 저장하거나 기록하지 않는다.
- 로그인, 비밀번호 재설정과 중요 작업에는 만료, 재시도 제한과 안전한 실패 처리를 둔다.
- 로그아웃 또는 권한 회수 후 기존 세션의 처리 방식을 명확히 한다.
- 인증 오류가 계정 존재 여부나 내부 정보를 과도하게 노출하지 않게 한다.

## 권한

- 모든 보호 작업은 신뢰할 수 있는 서버 측에서 권한을 확인한다.
- UI에서 버튼을 숨기는 것을 권한 통제로 간주하지 않는다.
- 사용자가 식별자를 바꿔 다른 사용자의 데이터를 읽거나 수정할 수 없는지 검증한다.
- 관리자와 중요한 데이터 변경 작업은 감사 가능한 기록을 남긴다.

## 입력, 출력과 파일

- 모든 외부 입력의 형식, 길이, 범위와 허용값을 검증한다.
- 데이터베이스 쿼리는 매개변수화하고 출력 문맥에 맞는 안전한 인코딩을 사용한다.
- 파일은 이름과 확장자만 신뢰하지 않고 크기, 실제 형식, 저장 경로와 접근 권한을 제한한다.
- 오류 응답과 로그에 스택, 내부 경로, 비밀정보와 개인정보를 노출하지 않는다.
- 요청 횟수와 자원 사용 제한이 필요한 엔드포인트를 검토한다.

## 개인정보

- 목적에 필요한 최소 정보만 수집한다.
- 수집 목적, 접근 주체, 보관 기간과 삭제 절차를 정한다.
- 운영 개인정보를 개발·테스트 환경에 그대로 복사하지 않는다.
- 로그, 분석 도구, 백업과 외부 서비스로 전달되는 개인정보를 확인한다.
- 전송 시 HTTPS를 사용하고 민감도에 따라 저장 암호화를 검토한다.

## 아동 및 AI 관련 데이터

- 아이 이름, 정확한 생년월일, 주소와 건강정보를 기본 입력으로 요구하지 않는다.
- 연령이 필요하면 가능한 경우 월령 또는 연령대처럼 목적에 충분한 최소 단위를 사용한다.
- 자유 문장에는 아동·보호자의 민감정보가 포함될 수 있다고 가정하고 저장, 로그와 외부 전송을 별도로 검토한다.
- AI 제공자에 전송하는 데이터는 답변에 필요한 최소 구조화 정보로 제한한다.
- 원문 질문 로깅은 기본 비활성화하고 활성화 전 목적, 동의, 보관 기간, 접근 권한과 삭제 방법을 정한다.
- 프롬프트, 모델 출력, 캐시와 관찰 도구에 개인정보가 남는 경로를 위협 시나리오에 포함한다.
- 비식별 사용자 식별자가 필요하면 계정 식별자나 개인정보 원문을 직접 사용하지 않는다.
- AI 출력은 승인된 근거 밖의 주장, 개인정보 노출과 안전 정책 위반을 검사한 뒤 제공한다.

## 보안 변경 완료 조건

- 위협 시나리오, 영향 사용자와 공격 경로를 기록한다.
- 정상 사용자와 권한 없는 사용자의 테스트를 모두 수행한다.
- 확인하지 못한 보안 항목을 안전하다고 표현하지 않는다.
- 중대한 보안 또는 법률 판단은 관련 전문가의 검토 대상으로 표시한다.
