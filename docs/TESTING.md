# 테스트 기준

## 기본 원칙

- 기대 결과를 테스트 실행 전에 정한다.
- 테스트가 존재한다는 사실과 실제 통과를 구분한다.
- 테스트 대역만 검증하고 실제 연결을 놓치지 않도록 테스트 층을 구분한다.
- 발견된 버그는 가능하면 실패하는 테스트로 먼저 재현한다.

## 테스트 층

### 단위 테스트

- 계산, 변환, 유효성 검사와 상태 전이를 검증한다.
- 정상값, 빈 값, 최소·최대값과 잘못된 형식을 포함한다.

### 통합 테스트

- 애플리케이션, 데이터베이스와 외부 인터페이스의 연결을 검증한다.
- 생성, 조회, 수정, 삭제와 실패 시 일관성을 확인한다.
- 인증과 권한은 UI 표시가 아니라 서버 측 동작까지 확인한다.

### 사용자 흐름 테스트

- 사용자의 시작점부터 핵심 결과까지 전체 과정을 검증한다.
- 로딩, 빈 데이터, 실패, 새로고침과 중복 요청을 확인한다.

### 회귀 테스트

- 변경 기능과 연관된 기존 핵심 기능을 다시 검증한다.
- 공통 코드나 데이터 모델 변경 시 영향받는 범위를 넓혀 실행한다.

## 테스트 결과 보고 형식

| 구분 | 명령 또는 절차 | 결과 | 비고 |
|---|---|---|---|
| 자동 테스트 | 미정 | 통과/실패/미실행 |  |
| 정적 검사 | 미정 | 통과/실패/미실행 |  |
| 빌드 | 미정 | 통과/실패/미실행 |  |
| 수동 확인 | 미정 | 통과/실패/미실행 |  |

실패와 미실행은 이유, 영향과 후속 조치를 함께 기록한다.
