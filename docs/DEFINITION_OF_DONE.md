# 완료 정의(Definition of Done)

모든 적용 항목을 충족해야 작업을 완료로 판정한다. 적용되지 않는 항목은 `해당 없음 — 이유`로 기록한다.

## 요구사항

- [ ] 목적, 범위와 제외 범위가 명확하다.
- [ ] 관찰하거나 테스트할 수 있는 완료 조건이 있다.
- [ ] 정상, 오류, 빈 상태와 권한 상황을 고려했다.
- [ ] 요청 범위를 벗어난 변경이 없다.

## 구현

- [ ] 기존 프로젝트 구조와 규칙을 따랐다.
- [ ] 임시 코드, 디버그 출력과 가짜 데이터가 남아 있지 않다.
- [ ] 비밀정보와 개인정보가 코드, 문서와 로그에 포함되지 않는다.
- [ ] 오류를 무시하거나 숨기는 처리가 없다.
- [ ] 새 의존성과 설정 변경의 이유 및 영향이 설명되어 있다.
- [ ] 데이터 변경의 호환성과 복구 방법을 검토했다.

## 테스트

- [ ] 정상 입력과 핵심 사용자 흐름을 검증했다.
- [ ] 빈 값, 잘못된 입력과 주요 경계값을 검증했다.
- [ ] 인증이나 권한이 관련되면 서버 측 권한 검사를 검증했다.
- [ ] 버그 수정에는 가능한 경우 재발 방지 테스트가 있다.
- [ ] 관련 자동 테스트를 실제로 실행했다.
- [ ] 기존 핵심 기능에 대한 회귀 테스트가 통과했다.
- [ ] 실패, 건너뜀, 경고와 실행하지 못한 테스트를 보고했다.

## 사용자 경험

- [ ] 로딩, 데이터 없음, 성공과 오류 상태가 이해 가능하다.
- [ ] 중복 클릭, 새로고침과 취소 행동을 안전하게 처리한다.
- [ ] 지원 대상 화면 크기와 입력 방식에서 확인했다.
- [ ] 사용자가 직접 확인해야 하는 사항을 전달했다.

## 보안과 운영

- [ ] `docs/SECURITY.md`의 관련 항목을 확인했다.
- [ ] 운영 환경과 데이터에 미치는 영향을 기록했다.
- [ ] 필요한 로그와 장애 관찰 수단이 있다.
- [ ] 배포 및 되돌리기 방법을 확인했다.
- [ ] 백업이 필요한 변경은 백업과 복원 방법을 확인했다.

## 완료 보고

- [ ] 구현 내용과 변경 파일을 보고했다.
- [ ] 완료 조건별 충족 여부를 보고했다.
- [ ] 테스트 명령과 실제 결과를 보고했다.
- [ ] 미검증 사항, 남은 위험과 제한을 보고했다.
- [ ] 필요한 경우 사용법과 되돌리는 방법을 보고했다.
