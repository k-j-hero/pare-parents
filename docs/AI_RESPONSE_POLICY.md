# AI 답변 및 비용·품질 기준

## 목적

Pare는 범용 모델의 기억에 의존해 육아 조언을 생성하지 않는다. 승인된 가이드를 안전 조건에 따라 검색하고, 필요한 경우에만 AI가 제한된 범위에서 분류하거나 표현을 조정한다.

## 답변 라우팅

```text
사용자 입력
  -> 입력 검증 및 최소 구조화
  -> 위험 신호 우선 검사
  -> 승인된 가이드 검색
  -> 연령·상황·안전·검토 상태 필터
  -> 답변 경로 선택
  -> 출력 검증
  -> 사용자 제공 또는 안전한 실패
```

모든 외부 AI 호출은 `packages/ai-gateway`를 통과한다. 웹, studio와 worker가 제공자 SDK를 직접 사용하지 않는다. Gateway는 개인정보 최소화, 작업별 모델 설정, 프롬프트 버전, 토큰 예산, timeout, 구조화 출력과 관찰 이벤트를 일관되게 강제한다.

### 경로 0 — AI 미사용

- 선택형 상황이나 정확한 가이드 식별자가 있는 경우 승인된 가이드를 그대로 표시한다.
- 첫 버전의 기본 경로다.
- 동일한 가이드 버전은 동일한 핵심 행동과 안전 문구를 제공한다.

### 경로 1 — 짧은 질문 분류

- 자유 문장에서 연령대, 주제, 행동, 맥락과 위험 신호 후보를 구조화한다.
- 모델 출력은 제한된 스키마로 검증한다.
- 분류 결과만으로 진단하거나 행동 지침을 생성하지 않는다.
- 모델 분류는 후보값이며 결정론적 위험 규칙과 서버 측 허용값 검사를 대체하지 않는다.

### 경로 2 — 승인된 가이드 재구성

- 검색된 승인 가이드의 허용된 필드만 모델에 전달한다.
- 모델은 표현과 순서를 조정할 수 있지만 새로운 원인, 진단, 효과 또는 행동 지침을 추가할 수 없다.
- 핵심 문장에는 연결된 가이드 버전과 근거 식별자가 유지되어야 한다.
- 가능한 경우 자유 문장 생성보다 승인된 content block 또는 claim ID를 선택·배열하게 한다.

### 경로 3 — 제한 또는 추가 질문

- 승인 가이드가 없거나 정보가 부족하거나 근거가 충돌하면 답을 추측하지 않는다.
- 안전 판단에 필요한 최소 질문만 추가하거나 현재 제공할 수 없는 범위를 알린다.
- 위험 가능성이 있으면 일반 가이드 생성을 중단하고 검증된 안전 안내로 전환한다.

## 검색 허용 조건

사용자 답변에는 다음 조건을 모두 만족하는 가이드만 사용한다.

- 공개 상태가 `published`다.
- 전문가 또는 지정 검토자의 승인이 유효하다.
- 사용자 상황과 적용 연령이 일치한다.
- 재검토 기한이 지나지 않았다.
- 연결된 핵심 출처가 철회 또는 무효 상태가 아니다.
- 안전 상태가 공개 가능으로 승인됐다.

원시 논문, 미검토 요약, 운영자 초안과 커뮤니티 글은 실시간 답변 검색 대상에서 제외한다.

검색 대상은 공개 시점에 생성된 불변 publication snapshot이다. 편집 테이블의 최신 상태를 실시간으로 조합하지 않으며 검색 결과, 본문과 인용은 같은 `publication_id`를 사용해야 한다.

## 모델 입력 최소화

- 논문 원문 대신 승인된 가이드의 관련 필드와 근거 ID만 전달한다.
- 검색 결과는 기본 1~3개로 제한하고 더 필요한 경우에만 확장한다.
- 전체 대화 대신 연령대, 현재 주제, 안전 상태와 이미 제공한 가이드 버전 등 최소 세션 상태를 사용한다.
- 이름, 생년월일, 주소, 의료기록과 자유 문장 원문을 불필요하게 재전송하지 않는다.
- 시스템 지침은 중복을 제거하고 정적 규칙을 앞부분에 배치한다.
- 출력은 구조화 스키마와 화면에 필요한 최대 길이를 갖는다.

## 캐시

AI 미사용 답변과 승인된 재구성 결과는 다음 값으로 캐시 키를 만든다.

```text
guide_version + age_band + situation_code + locale + response_format
```

- 가이드 버전, 안전 정책 또는 프롬프트 버전이 바뀌면 캐시를 무효화한다.
- 사용자 자유 문장이나 개인정보를 그대로 캐시 키와 로그에 넣지 않는다.
- 제공자 프롬프트 캐싱은 사용량의 캐시 읽기·쓰기 토큰과 실제 비용을 측정한 뒤 활성화한다.

## 모델 선택

- 모델 이름을 제품 규칙에 직접 고정하지 않고 작업 유형별 설정으로 관리한다.
- 분류는 평가 기준을 통과하는 가장 작은 모델을 우선한다.
- 표현 재구성은 정확성, 출처 보존과 안전 검사 기준을 통과하는 모델을 사용한다.
- 모델 크기나 추론 강도를 높이는 것은 대표 평가셋에서 측정 가능한 개선이 있을 때만 허용한다.
- 모델 또는 제공자 변경은 동일 평가셋으로 품질, 지연, 토큰과 비용을 비교하고 결정 기록을 남긴다.
- 공급자 또는 모델 장애 시 더 큰 모델로 무제한 재시도하지 않는다. 작업별 timeout, 최대 시도 수와 fallback 경로를 설정한다.

## 출력 검증

모델 출력은 사용자에게 전달하기 전에 다음을 검사한다.

- 스키마와 길이 제한을 만족하는가?
- 모든 행동 지침이 승인된 가이드에 존재하는가?
- 근거와 가이드 버전 식별자가 실제로 연결되는가?
- 적용 연령과 상황 제한을 벗어나지 않는가?
- 의료 진단, 치료 단정과 검토되지 않은 응급 처치를 포함하지 않는가?
- 효과를 과장하거나 불확실성을 제거하지 않았는가?
- 내부 프롬프트, 비밀정보, 개인정보와 내부 오류를 노출하지 않는가?

검증 실패 시 생성 답변을 폐기하고 원본 승인 가이드, 제한 응답 또는 안전 안내를 사용한다.

validator는 모델과 분리된 결정론 코드로 구현한다. 최소한 JSON schema, publication 상태, claim allowlist, 연령·locale, 길이와 금지 표현을 검사한다.

## 품질·비용 평가

토큰 절감은 다음 품질 기준을 유지할 때만 성공으로 판정한다.

- 상황 및 연령 분류 정확도
- 승인된 근거 밖의 주장 발생률
- 위험 신호 누락과 불필요한 위험 판정 비율
- 필수 행동과 금지 행동 포함률
- 근거 ID 및 가이드 버전 보존률
- 사용자의 이해도와 행동 발견 가능성
- 평균 및 상위 백분위 응답 시간
- 요청당 입력, 캐시 입력, 출력 및 추론 토큰
- 요청당 모델 비용과 AI 미사용 처리 비율

초기 토큰 예산은 구현 작업에서 대표 평가셋을 만든 뒤 확정한다. 안전 문구와 필수 근거를 제거해 예산을 맞추지 않는다.

모델·프롬프트·검색 변경은 오프라인 평가를 먼저 통과한 뒤 일부 트래픽 또는 shadow 평가로 검증한다. 기준 미달 시 이전 configuration ID로 즉시 되돌릴 수 있어야 한다.

## 운영 로그

개인정보를 제외하고 다음을 관찰한다.

- 선택된 답변 경로
- 가이드 및 프롬프트 버전
- 모델 설정과 호출 성공 여부
- 토큰 종류별 사용량, 지연과 비용
- 캐시 적중 여부
- 출력 검증 실패 사유
- 안전 경로 전환 여부

원문 질문 로깅은 기본값으로 사용하지 않으며 필요할 경우 별도의 목적, 보관 기간, 접근 권한과 동의 조건을 확정한다.

## 외부 제공자 검토

- API 데이터 보관, 학습 사용, 처리 지역과 삭제 조건을 계약 및 공식 문서에서 확인한다.
- 안정적인 비식별 사용자 식별자가 필요하면 개인정보를 직접 사용하지 않고 회전 또는 폐기 정책을 마련한다.
- 아동 관련 서비스에 적용되는 제공자 정책과 법률 요구를 공개 전 별도로 검토한다.
- 제공자 기능과 가격은 변경될 수 있으므로 구현 시점의 공식 문서를 다시 확인한다.

OpenAI를 사용할 경우 모델 선택, 캐시, 추론 설정과 비용 동작은 구현 시점의 [공식 OpenAI 모델 가이드](https://developers.openai.com/api/docs/guides/latest-model)를 다시 확인한다.
